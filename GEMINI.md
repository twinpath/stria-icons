# Gemini Agent Instructions - Stria Icons

Welcome. This document outlines the project structure and architectural constraints of the Stria Icons monorepo for Gemini coding agents.

## Core Principles

1. Core First Architecture: The source of truth is the raw SVG designs located in `icons/{style}/*.svg`.
2. Parity through Automation: Do not hand-write components in framework packages (`packages/react`, `packages/blade-icons`). They must be auto-generated by the compilers in `scripts/`.
3. Synchronized Versioning: All packages share the same version number during releases.
4. No Emojis: Do not write emojis in code, configuration, comments, logs, commit messages, or documentation.

## Directory Structure

- `icons/{style}/`: Source SVGs. Do not modify optimized files directly.
- `metadata/`: Metadata catalog (`icons.json`, `categories.json`).
- `packages/stria-icons/`: Core package containing CSS, sprites, and UMD/ESM/CJS bundles.
- `packages/react/`: React functional wrapper components.
- `packages/blade-icons/`: Laravel Blade wrapper views and service provider.
- `scripts/`: Compile scripts (SVG optimization, wrapper generation).

## Common Tasks

### 1. Adding or Modifying Icons
- Place or edit the source SVG in `icons/{style}/{icon-name}.svg`.
- Run `pnpm optimize` to run SVGO optimization.
- Run `pnpm metadata` to update the catalog.
- Run `pnpm build` to regenerate all packages (core, React, Blade).

### 2. Updating Build/Compiler Pipelines
- Modify the scripts in `scripts/build-core.mjs`, `scripts/build-react.mjs`, or `scripts/build-blade.mjs`.
- Never edit files in `packages/*/dist` or `packages/blade-icons/resources/svg` directly.
